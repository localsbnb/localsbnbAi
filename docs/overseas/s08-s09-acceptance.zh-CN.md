## 验收准备

1. Cursor/MCP 使用本地 `localsbnbAi/dist/run.cjs`，服务名推荐 **`Locals Overseas`**，不要用尚未包含本轮改动的公开 npm 包。已构建；若源码再次变化需重新构建，然后重启 MCP。
2. 确认 MCP 与海外站使用相同测试门店、Hudson dev。站点为 `https://overseas-dev.localhome.cn`；MCP 的 `LUKEYUN_API_BASE_URL` 指向 `https://hudson-dev.localhome.cn`。只用专用测试资源。
3. 工具列表应包含 S08 工具（含 `start_channel_connection` / `complete_channel_connection` 等）与 S09 写工具（含 `update_room_clean_state`）。缺失时先检查宿主加载路径、构建/重启、门店 `isBnb=1` 与认证结果；必要时改服务名刷新工具缓存。
4. 选定一个可修改价格方案、一个无订单/占用的测试房间，记录原始价格、库存与订单状态。ID 必须来自查询；不要自行编造。测试日期用门店时区。
5. 首轮只预览，检查页面没有变化；明确确认后才执行写入。`previewId` 10 分钟有效，绑定同一 MCP 进程/客户端/凭证/门店。金额为整数分（对用户展示带货币即可）。

## S08：自动打开浏览器页面，用户只回复“已完成”

当前默认交互：**“连接 Booking” → 打开浏览器页面（手机/桌面均可）→ 用户完成页面操作 → “已完成” → 自动查询比较 → 确认关联完成。** Trip / Agoda 相同。无需让用户提供 outPoiId、poiId 或重新描述渠道。

1. 用户说“连接 Booking”。LLM 调用 `start_channel_connection({"channel":"booking"})`；先读取并记录本门店该渠道 POI、门店/房型/产品关联快照，再尝试打开 `/linkbooking`。Trip / Agoda 分别为 `/linktrip`、`/linkagoda`。
2. LLM 仅提示：“请在打开的浏览器页面完成关联，完成后回来回复‘已完成’即可。”浏览器打开失败时才提供手动链接。页面使用现有浏览器登录态，若要求登录，用户登录与 MCP 相同门店；本工具不注入 Cookie。
3. 用户在浏览器完成关联后只回复“已完成”。LLM 调用 `complete_channel_connection({})`，系统自动选择当前渠道并查询比较，无需额外参数。
4. 新增 POI 或原有 POI 的门店/房型/产品映射、连接状态发生变化，且有门店映射、房型数据、全部房型状态为 3、无错误、接口返回的产品都有映射，才返回 `succeeded` 并结束。
5. 没有变化、只改了名称/时间戳、仅删除 POI、同步中或映射不完整均不算通过；返回 `pending` 并保留原快照，提示稍后或页面完成后再次回复“已完成”。关联异常返回 `needs_action`，处理后同样只回复“已完成”。

### S08 必测场景

| 场景 | 通过标准 |
|------|----------|
| Booking / Trip / Agoda 各一次正常连接 | 打开正确路径、按正确渠道查询；用户只需“已完成”，通过后结束，不再要求编号 |
| 操作前已有正常关联 | 用户未做任何操作便说“已完成”，不能把旧关联当成本次成功 |
| 原有 POI 补齐映射 | 不要求新增 POI；原有 POI 从未完成变为关联正常也能完成 |
| 同步延迟 | 第一次 pending，原快照不变；稍后再说“已完成”能继续核对 |
| 房型/价格方案未映射或状态异常 | 不报告全部完成；提示用户在浏览器页面完成/处理后再回复 |
| 浏览器打开失败 | 返回正确手动链接，保留快照；用户操作完成后仍能比较 |
| 重复发起连接 | 未结束时复用当前流程，不覆盖原快照；一次只跟进一个渠道 |
| 切换门店/凭证/客户端 | 不使用旧流程；不会将另一门店的变化判定为当前成功 |
| 重启 MCP 或超过 1 小时 | 记录不可用/过期时明确提示重新发起，不伪造完成 |
| 移动端浏览器（约 375 宽） | iOS Safari / Android Chrome：无整页横向溢出；主 CTA 可见可点；嵌套滚动不卡死；中英文界面无硬编码漏网。DevTools 375 布局已过；真机与完整渠道账号待补 |

## S09：正向用例

以下话术中的房间、房型、价格方案和日期需替换成实际测试资源；预览后核对身份、币种及金额再确认。

| 编号 | 用户第一句（只预览） | 预期工具与预览 | 用户确认后验收 |
|------|---------------------|----------------|----------------|
| P01 改价 | 查询测试房型 2026-11-10 至 11-11 的渠道价，记录原价。把选定方案这两天改为 10000 分，先给预览，不提交。 | 先 `query_room_prices`，再 `update_channel_prices`；显示方案/渠道、两天原价、新价与 previewId | 用户说“确认上述方案、两天改为 10000 分”；LLM 带原参数、`confirm=true`、previewId。回查价格与渠道日历，两天都正确，邻近日期不变 |
| P02 关房 | 查询测试房间 2026-11-10 至 11-11 房态，将这两天设为维修房，备注“验收测试”，先预览。 | `query_room_status_new` 后 `close_rooms`，`type=4`；展示具体房间、两天、维修类型和备注，无库存变更 | 用户明确确认后提交；两天有维修占用，其他房间/日期不变 |
| P03 开房 | 将刚才同一测试房间 2026-11-10 至 11-11 的维修占用解除，先预览。 | `open_rooms`；展示这两天现有维修占用；尚未提交时占用仍在 | 用户确认后提交；两天维修占用消失，重新查询房态确认没有新预订/其他占用 |
| P04 录单 | 为已恢复可售的测试房间录一张日租测试单，2026-11-10 入住、11-12 退房，客名“验收测试”，1 成人，已付 0，先计算报价并预览。 | `create_manual_order` 先查房间/占用并调用 calcPayout；显示 2 晚、门店币种、折扣后的房费、清洁费、税、总额/已付/未付、previewId；此时订单不存在 | 用户确认后仅保存一次；返回 orderId，再用 `get_order_details_v2` 与订单列表核对客人、房间、2 晚、手工渠道、金额；11-12 退房日不作为占房夜晚 |
| P05 脏净房 | 把测试房间（如 lhq）设为脏房，先预览；确认后再设为净房。 | `update_room_clean_state`；展示房间名、从→到状态与 previewId | 确认后回查今日房态 `cleanState`/`cleanStateLabel` 与预期一致 |

四个写工具成功响应为 `status=submitted`，表示后端已确认提交。`readBackStatus=read` 仅表示已经取回数据，仍需核对值；`failed` 表示回查失败，不能据此认定写入失败并重试。

P01 完成后，按已记录的原价重新预览并确认恢复；若两天原价不同，分别恢复。P02/P03 可用于相互验证，但必须选原本无占用的测试房间。P04 留在专用测试门店；清理由用户在 PC 正常流程处理，MCP 本期没有取消订单工具。

## S09：异常与边界用例

| 编号 | 测试方法 | 通过标准 |
|------|----------|----------|
| N01 未确认 | 四种操作只发起预览 | 没有 `/save`、`/close`、`/open` 写请求；PC 状态不变 |
| N02 无预览直接执行 | 测试工具调用 `confirm=true`，不带 previewId 或带任意字符串 | 拒绝写入；提示先获取有效预览 |
| N03 修改确认参数 | 预览 10000 分后，沿用 previewId 改成 12000 分确认 | 拒绝；需展示新预览并重新确认 |
| N04 过期/重启 | 预览后超过 10 分钟，或重启 MCP，再用旧 previewId | 拒绝；PC 无新增变更 |
| N05 重复确认 | 成功提交后再次使用同一 previewId | 不产生第二次写请求/重复订单；明确拒绝或在重新查询时发现当前状态不适用 |
| N06 价格/报价变化 | 预览后，在测试 PC 修改被预览的价格，或让报价发生变化，再确认旧预览 | 发现快照变化，拒绝使用旧预览 |
| N07 库存冲突 | 对已有订单或占用的测试日期尝试关房/录单；或在预览后制造测试占用，再确认 | 拒绝，不覆盖已有订单或占用 |
| N08 不可解除占用 | 尝试解除订单占用（2）或联动占用（3） | `open_rooms` 拒绝；仅允许手动占用类型 1/4/5 |
| N09 参数校验 | 无效日期、结束早于开始、超过 91 个日期、金额小数/负数、价格低于 10 分、已付超过订单总额、错误房间/房型组合 | 返回错误且不写入；房间不能跨门店使用 |
| N10 周几过滤 | P01 中设 `validWeekDays=[0,0,1,0,0,0,0]`（只周二；11-10 为周二） | 只更新 11-10，11-11 保持原价；预览同样只展示选中日期 |
| N11 权限不足 | 使用已知无写权限的测试账号/密钥 | 返回权限错误，不将 HTTP 200 当成业务成功 |
| N12 超时与回查失败 | 在模拟测试中制造写请求超时或写成功后的回查失败 | 写请求不自动重试；旧预览不可再次使用。回查失败返回 submitted + readBackStatus=failed；先查询结果再决定下一步 |

N02/N03/N05/N09 等可直接在 MCP 工具调试器传参；日常对话宿主应主动遵守预览确认，不应诱导模型绕过流程。N12 已有离线模拟测试，避免在真实录单中人为断网。
