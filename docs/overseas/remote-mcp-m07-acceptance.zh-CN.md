## 2. 验收前只需准备这些

1. **可访问的 HTTPS MCP 域名**及 TLS/代理；当前 `mcp.example` 是本机占位，不能直接给平台。PC 服务端也必须能访问 MCP 兑换接口。
2. 部署当前 MCP 代码和 PC 新增 `/ai/connect/[ticketId]`；PC dev 构建，两个服务配置相同的独立握手密钥。具体命令见[运行说明](../../deployment/remote/README.md)。不要把服务密钥或数据库密码放在对话中。
3. ChatGPT、Claude 的可用测试账号和自定义 MCP/插件权限；各自登记真实 client ID、精确回调 URI、允许 scope。现阶段采用预登记客户端，不启用自动 DCR/CIMD。
4. 两个 LocalsBnb 测试用户：A 至少可访问两个门店，B 访问另一门店；至少一个只读连接。每个待授权门店需已有有效 App Secret。
5. 一间可恢复的测试房、测试价格方案/订单，以及所需渠道测试账号。无账号的渠道标记“暂缓”，不能凭模拟结果勾通过。

**已有 Secret 的账号可开始本轮 M07。** 完全新账号自动开通仍缺 Hudson 幂等接口；当前会提示 `credential_setup_required`。不要为绕过此提示而重置原 Secret，否则可能影响本地部署。本轮未改 Hudson provider；该缺口必须在面向新用户公开发布前补齐。

## 3. 部署后先做连接验收

执行者：开发/运维，用户无需手抄 token。

1. `/healthz`、`/readyz` 为 200，ready 返回 `mode=business`；未知 Host 被拒绝。
2. 无令牌访问 `/mcp` 返回 401，并含受保护资源发现地址；发现数据 issuer/resource 使用正式 dev MCP 域名。
3. 确认业务开关为 1，001/002 迁移已应用，独立 key 保持不变；PC 配置的环境/密钥与 MCP 一致。
4. 确认 ChatGPT、Claude 分别登记客户端。平台回调值发生变化必须同步登记，不能放宽为通配回调。
5. 原 Cursor/本地 stdio 用既有方式启动，确认未要求配置数据库，也未要求更换 APP_SECRET。

ChatGPT 官方支持预登记 OAuth 客户端；平台提供的连接配置中使用对应 client ID、认证方式及回调。若通过插件门户测试，采用 `provided` 注册方式，client secret 仅在门户安全表单输入；不要将其写入插件包。公开上架资料属于 M08，本轮不提交审核。[OAuth 官方说明](https://developers.openai.com/plugins/build/auth)、[平台注册说明](https://developers.openai.com/plugins/deploy/submission)。

Claude 自定义连接器填写 HTTPS `/mcp`，OAuth client 选择 “Use your own OAuth client”，随后登录授权。组织账号可能需要管理员先添加。远程调用来自 Claude 云端，不能使用本机 localhost；完成配置后分别检查网页和手机可用性。[Claude 官方接入说明](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp)。

ChatGPT 手机端是否显示当前私有测试连接、支持哪些工具，以目标账号/客户端实际界面为验收结果；不要将“网页能连接”直接记为“手机已支持”。若平台入口未开放，记录“平台条件未满足”，先完成网页用例。

## 4. 用户验收顺序与话术

每个平台各执行一遍；手机与网页分别记录结果。模型负责调用并保存 sessionId、previewId，**用户不需要提供这些 ID**。

| 编号 | 用户怎么操作/说 | 通过标准 |
|---|---|---|
| A01 登录 | 点击连接，输入 LocalsBnb 账号；需要时输入 MFA；选择测试门店并同意 | 返回原平台；不要求粘贴 App Secret；连接检查的用户/门店正确 |
| A02 取消 | 新发起连接，在同意页点 Cancel | 不创建业务授权；平台显示取消；原连接/本地凭证不受影响 |
| A03 查询 | “查看本周房态和房价” | 查询正确门店，显示正确币种/门店时区；工具结果中没有凭证 |
| A04 两个对话 | 同账号分别开启对话甲、乙；甲用门店一、乙用已授权门店二 | 模型各自创建 session；切换甲不会改变乙；不共享旧预览 |
| A05 越权 | B 要求查询 A 的门店；只读连接要求改价 | 拒绝，不能借助传 campId、绝对 URL 或换工具绕过 |
| A06 新门店 | “切换到尚未授权的门店” | 提示先在浏览器单独授权；不能直接使用用户说出的 ID |
| A07 写预览 | “把测试房的清洁状态改为干净” | 先展示门店、房间、原状态和目标状态；未确认前 PC 不变化 |
| A08 写确认 | 确认预览，再回复“确认” | 只提交一次，返回操作结果；PC 查询到目标状态；测试后恢复原状态 |
| A09 变更预览 | 生成预览后在 PC 改变同一资源，再确认旧预览 | 拒绝旧预览，重新查询展示；不能覆盖新状态 |
| A10 其他写入 | 按 S09 测试改价、开关房、手工单、入住/退房/续住/换房 | 每项预览→确认→PC 回查；金额/日期/房间准确；远程入住退房一次一个明细 |
| A11 开渠道 | “我要关联 Airbnb/Booking/Trip/Agoda” | 保存基线并给可点击链接，说明网页完成后只回复“已完成” |
| A12 网页完成 | 点击链接，网页完成关联/授权/导入，回对话说“已完成” | 正确找到当前对话/渠道；存在完整门店/房型关联变化才成功 |
| A13 暂未关联 | 只登录或连接渠道账号，不导入/映射，回复“已完成” | 返回 pending 或 needs_action；不能把账号变化当完成 |
| A14 链接失效 | 120 秒后打开、重复兑换或 link preview 消耗后重开 | 旧 ticket 被拒绝；重新请求开链得到新 URL，保留原基线 |
| A15 登录态 | 完成开链后等待 ticket 过期，再操作网页 | PC Cookie 与绑定门店仍有效；AI 初始化不调用无权限 `/camps/get` |
| A16 环境隔离 | dev 浏览器历史保存 `localsbnb_api_env=prod` 后开新链接 | 新握手、回调及后续网页请求均用 hudson-dev，不发送 dev token 到 prod |
| A17 返回手机 | 手机外部浏览器完成网页操作，再切回原对话回复“已完成” | 不要求复制账号/房源 ID，仍找到原流程；分别记录 iOS/Android |
| A18 刷新与撤销 | 等待访问令牌到期再查询；随后断开连接 | 正常串行刷新；撤销后旧 access/refresh 及未兑换 ticket 均不可用 |

A10 的细化用例沿用 [S08/S09 验收文档](./s08-s09-acceptance.zh-CN.md)。本轮不要为测试在非测试房/生产环境创建订单或推送渠道变更。

## 5. 开发执行的故障验收

| 编号 | 场景 | 通过标准 |
|---|---|---|
| F01 跨实例/重启 | 创建预览与渠道基线，重启服务后继续 | 加密密钥不变时仍恢复；重新开链接不丢基线 |
| F02 并发确认 | 两次相同确认同时到达 | 同一预览最多一个外部提交，其余拒绝或返回既有结果 |
| F03 结果未知 | 替身模拟提交后断线/进程退出，查询状态 | unknown/running，不自动再写；先查 PC 资源；不以新会话绕过 |
| F04 存储故障 | 测试环境暂停 Redis/PG，再查询 | ready 503，认证/写入失败关闭；无内存或共享账号回退 |
| F05 回查失败 | 替身返回写成功、回查失败 | 显示已提交但回查失败，不重新提交 |
| F06 服务端兑换 | 错误密钥、环境不一致、陌生路径、重复 ticket | 无 Cookie；拒绝响应不含凭证；PC props 不含 Token |
| F07 本地兼容 | 停掉远程服务再启动原 stdio | 原部署仍能初始化与使用，不依赖远程 PG/Redis |

自动化已覆盖其中主要逻辑；真实代理/重启及手机行为仍需各自证据。前端链接预览器可能执行非 prefetch GET，M07 要记录目标平台是否提前消费 ticket；若复现影响正常点击，需要改为用户显式继续后兑换，再验收，不能仅以重开链接掩盖问题。
